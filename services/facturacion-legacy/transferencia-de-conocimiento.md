# Plan de transferencia de conocimiento

**Meta:** bus factor de al menos 2 antes de la salida del responsable actual.

## Sesiones

1. Recorrido del módulo: arquitectura general y puntos de entrada.
2. Mapa de dependencias: qué otros servicios llaman a facturación.
3. Procedimientos de operación: despliegue, rollback y casos de fallo conocidos.
4. Pair programming: un ingeniero hace un cambio real con acompañamiento.
5. Revisión: el segundo ingeniero documenta lo que entendió y el responsable corrige.

## Entregables

- [ ] README con mapa de dependencias completo
- [ ] Runbook de despliegue y rollback
- [ ] ADRs de las decisiones históricas que aún importan
- [ ] Grabación o notas de cada sesión, enlazadas desde este archivo
